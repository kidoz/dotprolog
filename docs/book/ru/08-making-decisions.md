# Глава 8 — Принятие решений

Всё, что вы писали до сих пор, обращается со всеми ответами одинаково: правило описывает, что
истинно, а Пролог находит все способы сделать это истинным. Но настоящим программам нужно ещё и
*выбирать*: сделать одно, если выполняется условие, и другое — если нет; остановиться после
первого ответа; вежливо отступить, когда что-то пошло не так. Эта глава — о таких выборах:
*или*, если-то-иначе, отрицание, отсечение и ошибки, которые можно перехватить.

Примеры используют семейную базу данных из главы 2. Держите эти факты в начале каждой программы
этой главы:

```prolog
parent(pam, bob).
parent(tom, bob).
parent(tom, liz).
parent(bob, ann).
parent(bob, pat).
parent(pat, jim).

female(pam).
female(liz).
female(ann).
female(pat).
male(tom).
male(bob).
male(jim).
```

## Как сказать *или*

Вы говорите *или* с самой главы 3, не замечая этого. Два правила с одинаковой головой означают
*подойдёт любое из двух*:

```prolog
person(X) :- male(X).
person(X) :- female(X).
```

Некто является человеком, если это мужчина *или* женщина. Добавьте эти два правила к семейной
базе данных вместе с `main :- forall(person(P), (write(P), nl)).` — и появится каждый член
семьи:

```text
tom
bob
jim
pam
liz
ann
pat
```

Есть в Прологе и такое *или*, которое пишется внутри одного правила: точка с запятой, `;`. Вот
маленькая программа о погоде:

```prolog
:- initialization(main).

today(cloudy).

can_see_sky :- today(sunny) ; today(cloudy).

main :-
    can_see_sky,
    write('we can see the sky'), nl.
```

```text
we can see the sky
```

Читайте `;` как *или*: небо видно, если сегодня солнечно или сегодня облачно. Пролог сначала
пробует левую сторону; только когда она терпит неудачу, он берётся за правую. Поскольку
`today(sunny)` терпит неудачу, а `today(cloudy)` успешна, `can_see_sky` успешна.

Слово о стиле: когда предикат просто перечисляет альтернативы, отдельные предложения — как у
`person/1` выше — обычно читаются лучше, чем одно предложение, набитое точками с запятой. А вот
где точка с запятой по-настоящему отрабатывает своё место, вы увидите прямо сейчас.

## Если, то, иначе

Часто нужно *или* с приложенным к нему решением: если условие выполняется, сделай одно, иначе —
другое. Пролог записывает это стрелкой внутри скобок:

```prolog
:- initialization(main).

sign(N, S) :-
    ( N < 0 ->
        S = negative
    ;
        S = 'zero or positive'
    ).

main :-
    sign(-7, A), write(A), nl,
    sign(3, B), write(B), nl.
```

```text
negative
zero or positive
```

Форма такова: `( Condition -> Then ; Else )`. Пролог пробует условие. Если оно успешно,
выполняется только часть *то*; если терпит неудачу — только часть *иначе*. Либо одно, либо
другое, никогда оба, — и, в отличие от простого `;`, Пролог не вернётся позже попробовать
пропущенную ветку. Скобки — часть идиомы: пишите их всегда.

## Цепочки условий

Условия естественно выстраиваются в цепочки. Пусть программа лояльности делит покупателей по
баллам:

```prolog
:- initialization(main).

tier(Score, T) :-
    ( Score >= 1000 -> T = gold
    ; Score >= 500  -> T = silver
    ; T = bronze
    ).

main :-
    tier(1200, A), write(A), nl,
    tier(700, B), write(B), nl,
    tier(80, C), write(C), nl.
```

```text
gold
silver
bronze
```

Читайте сверху вниз, как список случаев: 1000 и больше — золото; иначе 500 и больше — серебро;
иначе бронза. Побеждает первое успешное условие, а у последней строки — той, что на все
остальные случаи, — стрелки нет вовсе. Такая цепочка — одна из самых полезных форм в Прологе, и
вы ещё встретите её в главе с проектом.

## Что нельзя доказать: `\+`

Ещё в главе 2 вы познакомились с замкнутым миром Пролога: если факта нет в базе данных и никакое
правило не может его вывести, Пролог отвечает *false*. Не *неизвестно* — ложь. Оператор `\+`
превращает эту идею в инструмент, которым можно пользоваться внутри правила: `\+ Goal` успешна
ровно тогда, когда `Goal` доказать нельзя. Читайте это как *нет способа показать, что…*

У Джима в нашей базе данных нет детей, и `\+` может об этом сказать:

```prolog
main :-
    ( \+ parent(jim, _) ->
        write('jim has no children')
    ;
        write('jim has children')
    ), nl.
```

```text
jim has no children
```

А теперь предупреждение, и оно стоит целого абзаца: **`\+` никогда не связывает переменную.**
Можно понадеяться найти того, кто *не* является родителем Боба, спросив `\+ parent(X, bob)`:

```prolog
main :-
    ( \+ parent(X, bob) -> write(X) ; write('no answer') ), nl.
```

```text
no answer
```

Почему? `X` не связана, поэтому `parent(X, bob)` доказать *можно* — Пэм является родителем
Боба, — и, следовательно, `\+ parent(X, bob)` терпит неудачу. `\+` спрашивает только одно:
*можно это доказать или нет*; сам он ничего не доказывает, и потому ему нечего вернуть в виде
связываний. Это проверка, а не вопрос.

Лекарство — шаблон, которым вы будете пользоваться постоянно: *сначала породи, потом проверь*.
Сперва назовите кандидата обычной целью, затем отфильтруйте с помощью `\+`:

```prolog
childless(X) :- person(X), \+ parent(X, _).
```

Здесь `person(X)` по очереди предлагает каждого члена семьи, а `\+ parent(X, _)` оставляет
только бездетных. Проверим пару человек:

```prolog
main :-
    ( childless(jim) -> write('jim is childless') ; write('jim has a child') ), nl,
    ( childless(bob) -> write('bob is childless') ; write('bob has a child') ), nl.
```

```text
jim is childless
bob has a child
```

А собрать *всех* бездетных в один список — работа для следующей главы.

## Только один ответ: `once/1`

Иногда достаточно любого одного ответа. У запроса `parent(P, bob)` два ответа, Пэм и Том;
обёртка `once/1` берёт первый и закрывает дверь перед остальными:

```prolog
main :-
    once(parent(P, bob)),
    write(P), nl.
```

```text
pam
```

Используйте `once`, когда правилу нужен лишь *какой-нибудь* ответ — доказательство, что решение
существует, — а лишние ответы при бэктрекинге были бы не подарком, а помехой.

## Отсечение

У Пролога есть более старый и более острый инструмент, обрубающий альтернативы: отсечение
(cut), записываемое `!`. Как цель оно всегда успешно — а в качестве побочного эффекта
*фиксирует* выбор, сделанный к этому моменту в текущем предложении. После отсечения Пролог не
станет пробовать другие предложения этого предиката, как и другие ответы для целей слева от
отсечения.

Классический пример — найти большее из двух чисел:

```prolog
:- initialization(main).

max(X, Y, X) :- X >= Y, !.
max(_, Y, Y).

main :-
    max(3, 7, A), write(A), nl,
    max(9, 2, B), write(B), nl.
```

```text
7
9
```

Первое предложение говорит: если `X` не меньше `Y`, ответ — `X`, а `!` добавляет: *и хватит
искать*. Без отсечения подошли бы оба предложения: спросив все ответы для `max(9, 2, M)`, вы
получили бы `9`, а затем, что нелепо, `2` — второе предложение понятия не имеет, что первое уже
преуспело. Отсечение придаёт второму предложению смысл *иначе*.

Отсечение — инструмент мощный и знаменитый тем, как легко им злоупотребить: поставленное
небрежно, оно молча выбрасывает нужные вам ответы. Честный совет на сегодня: когда вы имеете в
виду *если-то-иначе* — так и пишите если-то-иначе. Вот версия `max`, которая ведёт себя так же,
но носит свою логику на виду:

```prolog
max(X, Y, M) :- ( X >= Y -> M = X ; M = Y ).
```

Отсечения будут попадаться вам в чужом коде, так что читать их нужно уметь; писать же их в этой
книге вам почти не придётся.

## Когда что-то ломается нарочно

В главе 1, в упражнении 3, вы написали `wrote` вместо `write` и встретили вот это:

```text
error: existence_error(procedure, wrote/1)
```

Программа остановилась. Но вот хорошая новость, ради которой написан этот раздел: ошибка в
Прологе — не обязательно конец. Ошибки выбрасываются, а всё выброшенное можно перехватить.

Всю работу делают два предиката. `throw(Term)` бросает то, чем программа занималась, и
выбрасывает `Term` наружу. `catch(Goal, Pattern, Recovery)` выполняет `Goal`; если во время
выполнения что-то выброшено и оно сопоставляется с `Pattern`, вместо остановки программы
выполняется цель `Recovery`.

Выбросить можно что угодно:

```prolog
:- initialization(main).

bake(_) :-
    throw(oven_too_hot).

main :-
    catch(bake(cake), oven_too_hot, (write('turn the oven down'), nl)).
```

```text
turn the oven down
```

Ошибки, которые выбрасывает сам Пролог, имеют одну общую форму, закреплённую стандартом ISO:
`error(WhatWentWrong, Context)`. Первый аргумент говорит, что случилось, —
`existence_error(procedure, wrote/1)` в сообщении выше, — а второй содержит дополнительный
контекст, который обычно можно не читать. Зная форму, вы можете перехватить ошибку из главы 1 и
жить дальше:

```prolog
:- initialization(main).

main :-
    catch(wrote(hello),
          error(existence_error(procedure, What), _),
          (write('missing predicate: '), write(What), nl)),
    write('still running'), nl.
```

```text
missing predicate: wrote/1
still running
```

Заметьте: `What` в образце — переменная. Перехват унифицирует выброшенный терм с образцом, и
образец сам сообщает, *какого* предиката не хватало.

Второй ошибкой каждого новичка одаривает арифметика. Деление на ноль:

```prolog
main :-
    X is 1 / 0,
    write(X), nl.
```

```text
error: evaluation_error(zero_divisor)
```

Обёрнутое в `catch`, деление становится безопасным:

```prolog
:- initialization(main).

safe_divide(X, Y, R) :-
    catch(R is X / Y, error(evaluation_error(zero_divisor), _), R = undefined).

main :-
    safe_divide(10, 4, A), write(A), nl,
    safe_divide(10, 0, B), write(B), nl.
```

```text
2.5
undefined
```

Когда деление получается, `catch` невидим. Когда оно выбрасывает ошибку, выполняется цель
восстановления `R = undefined`, и вызывающий получает атом `undefined` вместо аварии.
Перехватывайте ошибки там, где вы можете сделать с ними что-то осмысленное; во всех остальных
местах пусть летят — сообщение с именем файла и термом ошибки при отладке нужно вам ровно в
таком виде.

!!! note "Неудача и ошибки — разные вещи"
    Цель, которая *терпит неудачу*, — это обычная жизнь Пролога: она просто означает
    *недоказуемо*, и бэктрекинг продолжается. *Ошибка* же пролетает мимо всего этого, оставляя
    цели одну за другой, пока её не остановит `catch`. `\+` работает с неудачей; `catch` — с
    ошибками. Держите эти две идеи порознь — и избежите настоящей путаницы.

## Упражнения

1. Расширьте `tier/2` уровнем `platinum` для 2000 баллов и выше и проверьте, что 2500, 1200,
   700 и 80 баллов попадают в правильные уровни.
2. Напишите `abs_value(N, A)` через если-то-иначе, чтобы `A` было равно `N` без знака минус:
   `abs_value(-5, A)` должно давать `5`, а `abs_value(3, A)` — `3`.
3. Напишите `has_son(X)` — истинно, когда у `X` есть сын. Затем, используя `\+` и шаблон
   «породи, потом проверь», напишите `sonless(X)` — истинно, когда `X` — человек без сыновей.
   Проверьте Тома и Боба по отдельности, так же, как эта глава проверяла `childless`.
4. Напишите `min/3` в стиле `max/3`: сначала с отсечением, потом через если-то-иначе. Убедитесь,
   что обе версии дают один ответ для `min(4, 9, M)`.
5. Напишите `ticket(Age)`, печатающий `child` для возраста младше 13 и `adult` иначе, — но
   выбрасывающий терм `bad_age`, если `Age` отрицателен. В `main` вызовите его внутри `catch`,
   чтобы `ticket(-3)` печатал вежливую жалобу, а не останавливал программу.
6. С чем `once(parent(tom, C))` свяжет `C`? Догадайтесь по порядку фактов, затем проверьте.
